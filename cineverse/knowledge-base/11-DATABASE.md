# 11 — Database

This section covers the PostgreSQL schema (`supabase-schema.sql`) and the seed script (`scripts/seed-products.mjs`).

---

## Schema Overview

The database has 5 tables: `profiles`, `products`, `orders`, `reviews`, `coupons`. All tables have Row Level Security (RLS) enabled.

---

## Table: `profiles`

**Purpose:** Stores user profile data linked to Supabase Auth users.

```sql
CREATE TABLE profiles (
  id UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  email TEXT,
  role TEXT NOT NULL DEFAULT 'customer' CHECK (role IN ('customer','staff','manager','admin')),
  avatar TEXT,
  banned BOOLEAN DEFAULT false,
  suspended BOOLEAN DEFAULT false,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

**Column details:**
- `id` — Primary key that references `auth.users(id)` with `ON DELETE CASCADE`. When the auth user is deleted, the profile is automatically deleted. This is a 1:1 relationship — one profile per auth user.
- `name` — Display name, required.
- `email` — Mirrored from auth on registration (nullable in case auth handle changes).
- `role` — Access level. Defaults to `'customer'`. Check constraint limits to 4 values: `customer`, `staff`, `manager`, `admin`.
- `banned` / `suspended` — Account status flags for moderation.
- `created_at` / `updated_at` — Auto-set timestamps. `updated_at` is maintained by the `update_updated_at` trigger.

**How it's created:** When a user registers via `registerUser()` in `auth.js`, after Supabase creates the auth user, a profile row is inserted with `role: 'customer'`. The id matches the auth user's id.

## Table: `products`

**Purpose:** Stores product data synced from external APIs.

```sql
CREATE TABLE products (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  external_id TEXT,
  title TEXT NOT NULL,
  description TEXT,
  price NUMERIC(10,2) NOT NULL,
  category TEXT NOT NULL CHECK (category IN ('movie','book','manga','comic')),
  image TEXT,
  images JSONB DEFAULT '[]',
  stock INT DEFAULT 0,
  rating NUMERIC(3,1) DEFAULT 0,
  rating_count INT DEFAULT 0,
  featured BOOLEAN DEFAULT false,
  metadata JSONB DEFAULT '{}',
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(category, external_id)
);
```

**Column details:**
- `id` — UUID generated by the database.
- `external_id` — The ID from the source API (TMDB movie ID, Google Books volume ID, Jikan MAL ID, Open Library work key). Used for deduplication with the `UNIQUE(category, external_id)` constraint.
- `price` — Numeric with 2 decimal places (though prices are whole Naira in practice).
- `category` — Limited to 4 values matching product types.
- `images` — JSONB array for multiple screenshots (movies).
- `metadata` — JSONB for API-specific data (director, publisher, genres, etc.).
- `UNIQUE(category, external_id)` — Prevents duplicate products from the same source.

**Usage:** Currently, products are fetched live from external APIs rather than queried from this table. The seed script populates it for future self-hosted product management.

## Table: `orders`

**Purpose:** Stores customer orders.

```sql
CREATE TABLE orders (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES profiles(id) NOT NULL,
  items JSONB NOT NULL,
  total_amount NUMERIC(10,2) NOT NULL,
  status TEXT DEFAULT 'pending' CHECK (status IN ('pending','processing','shipped','delivered','cancelled')),
  shipping_info JSONB,
  payment_method TEXT,
  payment_ref TEXT,
  coupon_id UUID,
  discount NUMERIC(10,2) DEFAULT 0,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

**Column details:**
- `user_id` — Foreign key to profiles. NOT NULL — every order belongs to a user.
- `items` — JSONB array storing the cart snapshot at time of purchase. Each item has: `productId`, `title`, `price`, `quantity`, `image`, `category`. Stored as JSON rather than a normalized table because order history should not change if product data changes.
- `status` — Lifecycle: `pending` → `processing` → `shipped` → `delivered`, or → `cancelled`.
- `shipping_info` — JSONB object with shipping address (name, address, city, state, phone).
- `payment_ref` — Paystack transaction reference for card payments.
- `coupon_id` — Foreign key to coupons (nullable, coupon system not yet implemented in UI).
- `discount` — Discount amount applied (future use).

**Order creation flow:** See Checkout in [06-PAGES.md](./06-PAGES.md#checkoutjsx).

## Table: `reviews`

**Purpose:** User product reviews and ratings.

```sql
CREATE TABLE reviews (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES profiles(id) NOT NULL,
  product_id UUID REFERENCES products(id) NOT NULL,
  rating INT NOT NULL CHECK (rating >= 1 AND rating <= 5),
  comment TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(user_id, product_id)
);
```

**Key constraint:** `UNIQUE(user_id, product_id)` — each user can only review a product once. If they submit again, it's an update (upsert pattern).

---

## Table: `coupons`

**Purpose:** Discount coupon codes.

```sql
CREATE TABLE coupons (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  code TEXT UNIQUE NOT NULL,
  type TEXT NOT NULL CHECK (type IN ('percentage','fixed')),
  value NUMERIC(10,2) NOT NULL,
  min_amount NUMERIC(10,2) DEFAULT 0,
  max_uses INT DEFAULT 100,
  used_count INT DEFAULT 0,
  expires_at TIMESTAMPTZ,
  active BOOLEAN DEFAULT true,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

**Note:** Coupon system is not currently implemented in the frontend UI. The checkout page doesn't include a coupon input. This is a future feature with the schema ready.

## Triggers

### `update_updated_at()`

```sql
CREATE OR REPLACE FUNCTION update_updated_at()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = NOW();
  RETURN NEW;
END;
$$ language 'plpgsql';
```

A trigger function that automatically sets `updated_at` to the current timestamp on any UPDATE. Applied to `profiles`, `products`, and `orders` tables.

## Row Level Security (RLS) Policies

### Profiles

| Policy | Action | Rule |
|--------|--------|------|
| Viewable by everyone | SELECT | `true` (public read) |
| Users can update own profile | UPDATE | `auth.uid() = id` |
| Admins can update any profile | UPDATE | User's profile role = 'admin' |
| Admins can delete profiles | DELETE | User's profile role = 'admin' |

**Why public profile read?** Profiles are needed for reviews (to show reviewer name) and orders. There's no sensitive data in profiles (no passwords, no payment info).

### Products

| Policy | Action | Rule |
|--------|--------|------|
| Viewable by everyone | SELECT | `true` (public read) |
| Admins can insert | INSERT | User's role = 'admin' |
| Admins can update | UPDATE | User's role = 'admin' |
| Admins can delete | DELETE | User's role = 'admin' |

### Orders

| Policy | Action | Rule |
|--------|--------|------|
| Users can view own orders | SELECT | `auth.uid() = user_id` |
| Staff can view all orders | SELECT | User's role IN ('staff','manager','admin') |
| Users can create own orders | INSERT | `auth.uid() = user_id` |
| Staff can update orders | UPDATE | User's role IN ('staff','manager','admin') |

**Key design:** Users see only their own orders. Staff (staff, manager, admin) see all orders. This means dashboard orders pages use staff-level API calls.

### Reviews

| Policy | Action | Rule |
|--------|--------|------|
| Viewable by everyone | SELECT | `true` |
| Any authed user can insert | INSERT | `auth.uid() = user_id` |
| Users can update own | UPDATE | `auth.uid() = user_id` |
| Users can delete own | DELETE | `auth.uid() = user_id` |
| Admins can delete any | DELETE | User's role = 'admin' |

### Coupons

| Policy | Action | Rule |
|--------|--------|------|
| Viewable by everyone | SELECT | `true` |
| Admins can manage | ALL | User's role = 'admin' |

## Seed Script (`scripts/seed-products.mjs`)

**Purpose:** Populates the Supabase `products` table with data from TMDB, Google Books, Jikan, and Open Library.

**Not currently present in the codebase** — the script and `src/test/` directory were present in initial analysis but may have been removed. If created, it would:

3. Fetch top manga from Jikan and insert with `category: 'manga'`
4. Fetch comics by subject from Open Library and insert with `category: 'comic'`
5. Use upsert (on conflict `category, external_id` do nothing) to avoid duplicates
